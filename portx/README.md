# portx

输入端口，查出占用它的应用与进程。默认只读；加 `-k` 才结束进程，系统级端口也只在这时拒绝，必须显式加 `--force`。

## 用法

```
portx                        打开主菜单
portx 8080                   查看占用 8080 的进程与应用信息
portx 8080 8081 8082         一次给多个端口，逐个查询
portx -l                     列出全部监听端口
portx -l -u                  连 UDP 一起列
portx -u 5353                连 UDP 端口一起查
portx -n 8080                只列出占用进程，不发信号
portx -k 8080                结束占用 8080 的进程
portx -k -9 8080             直接 SIGKILL，不等进程收尾
portx -k -s INT 8080         发指定信号，名字或编号都行
portx -k -t 10 8080          信号发出后等 10 秒，默认 5 秒
portx -k -y 8080             跳过确认，超时后补发 SIGKILL 也不再追问
portx -k --force 3306        受保护端口，确要动就显式放行
portx --help                 显示帮助
```

## 终端菜单

不带参数进入终端菜单，可以选择按端口查询或浏览当前监听端口。列表只显示端口数据，选中后可查看详情或结束进程；详情页里还能进入进程所在目录、切换 UDP、刷新与返回。当前可用的操作与按键以界面提示为准。

没有终端时自动退回编号输入。

## 查询

先确认端口是否在监听，再读取占用进程的应用与程序信息；权限不足时只报告能拿到的部分，不做猜测。

加 `-u` 时 TCP 与 UDP 各查一遍。查询任何端口都不需要 `--force`。

`-l` 扫描全部监听端口，按端口顺序输出。

## 几种查不到进程的情形

- 端口没人监听：提示无监听，以退出码 1 退出。
- 有监听但拿不到进程：非 root、容器映射的端口等情况下只报告，不猜测。
- 进程不能动：init、本脚本自身与父进程会被跳过。
- 信号没送到：逐条报告，不中断其余端口。

## 结束进程

加 `-k` 后先发 SIGTERM，让进程自己收尾。超过 `--timeout` 秒仍未退出时，再询问要不要补发 SIGKILL。

如果 stdin 不是终端（管道、脚本、CI），确认一律按否处理。这种场合要一次处理完，就加 `-y`。`-k -9` 跳过等待与追问，直接强杀，对数据库和正在写文件的进程要慎用。

`-s`、`-t`、`-f`、`-y` 只用于 `-k`，单独使用会按用法错误退出。

## 保护系统级端口

两个来源，规则一样，只在 `-k` 时生效，都必须显式加 `--force` 才放行：

- 端口 `0` 到 `1023`，即内核只允许 root 绑定的特权端口段。
- 常见服务的默认端口：ftp、ssh、telnet、smtp、dns、http、https、nfs、mysql、postgresql、redis、mongo、kafka、elasticsearch。

开发常用端口不在保护范围内。

## 退出码

| 码 | 含义                                                         |
| -- | ------------------------------------------------------------ |
| 0  | 查到或处理成功                                               |
| 1  | 没监听、拿不到 pid、信号没送到或进程没退出                   |
| 2  | 用法错误，与 `mvnx` 一致                                     |
| 3  | `-k` 撞上受保护端口，且没有 `--force`                        |

多个端口一起给时，只要有一个没查到或没处理成，整体退出码就不是零。撞上保护端口（退出码 3）比普通失败（退出码 1）更值得调用方看见，两者同时出现时按 3 退出。
