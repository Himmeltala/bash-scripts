# portx

按端口查占用进程，或浏览当前监听端口。默认只读；`-k` 才结束进程，系统级端口还要 `--force`。

## 用法

```
portx                        打开菜单
portx 8080                   查占用 8080 的进程
portx 8080 8081              一次查多个端口
portx -l                     列出全部监听端口
portx -l -u                  连 UDP 一起列
portx -u 5353                连 UDP 一起查
portx -n 8080                只列进程，不发信号
portx -k 8080                结束进程（先 SIGTERM）
portx -k -9 8080             直接 SIGKILL
portx -k -s INT 8080         发指定信号
portx -k -t 10 8080          等 10 秒，默认 5 秒
portx -k -y 8080             跳过确认
portx -k --force 3306        放行受保护端口
```

## 菜单与查询

不带参数进菜单，可选按端口查询或浏览监听端口；选中后可看详情、结束进程、进入进程目录、切 UDP、刷新。没有终端时退回编号输入。

先确认端口在监听，再读进程的应用与程序信息；权限不足时只报能拿到的部分。`-u` 时 TCP 与 UDP 各查一遍；查询任何端口都不需要 `--force`。

查不到进程的常见情形：端口没人监听（退出码 1）、非 root 或容器映射拿不到进程信息、进程是 init 或本脚本自身（跳过）。多个端口一起给时，只要有一个失败整体就不是零。

## 结束进程

`-k` 先发 SIGTERM，超时后询问是否补 SIGKILL。stdin 不是终端时确认一律按否，要一次处理完就加 `-y`；`-k -9` 跳过等待直接强杀。`-s`、`-t`、`-y` 只能和 `-k` 一起用。

受保护端口只在 `-k` 时生效，必须加 `--force`：0-1023 与常见服务默认端口（ftp、ssh、smtp、dns、http、https、mysql、postgresql、redis、mongo、kafka、elasticsearch 等）。

## 退出码

| 码 | 含义 |
| -- | --- |
| 0 | 成功 |
| 1 | 没监听、拿不到 pid、信号没送到或进程没退出 |
| 2 | 用法错误 |
| 3 | `-k` 撞上受保护端口且没有 `--force` |

多个端口同时出错时，3 优先于 1。
