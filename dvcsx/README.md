# dvcsx

网页里看 SVN 工作副本或 Git 仓库的未提交变更与提交日志，点文件直接看差异；也能拉取、推送、切换分支、更新、提交，浏览目录、看代码内容。

## 用法

```
dvcsx                 起网页界面
dvcsx web             同上
dvcsx web --host 127.0.0.1 -p 8771
```

| 选项 | 说明 |
| --- | --- |
| `--host 地址` | 监听地址，默认 `0.0.0.0`；只想本机用就写 `127.0.0.1` |
| `-p, --port 端口` | 监听端口，默认 0 由系统挑一个空闲的 |
| `-o, --open` | 起来后打开默认浏览器 |
| `--allow-write` | 允许其他机器发起拉取、推送、切换分支、更新与提交；默认只有本机能写 |
| `--json` | 只打一行地址信息，给脚本起服务用 |

页面没有登录，默认绑所有网卡，同一网络里能连上的人都能看到工作副本里的差异。只想本机用就加 `--host 127.0.0.1`。

写操作默认只接受从本机发出的请求，别的机器打开页面只能看，不能拉取、推送、切换分支、更新或提交。确认整个网络可信时再加 `--allow-write`，否则别人能改你的工作副本与远端仓库。

## 加工作副本

左侧「添加」，选一个有 `.svn` 的目录，或一个 Git 仓库目录。加的时候先跑 `svn info`，不是 SVN 再按 `git rev-parse` 认，两样都不是就拒绝。登记只记目录本身，不动工作副本。

Git 登记的是仓库里的某个目录，可以就是仓库根，也可以是子目录；是子目录时只显示这个目录底下的改动与提交。

已登记的目录可以移出列表，工作副本本身不受影响。

左侧工作区可以点右键设置别名、复制相对路径或绝对路径。相对路径以家目录为基准；别名存在状态文件 `~/.cache/dvcsx/web/state.json` 里，只影响页面显示。

## 变更

列出工作副本里未提交的改动：改动的、新增的、删除的、重命名或替换的、冲突的、未纳入版本控制的。点一行看差异。

- 已纳入版本控制的文件，SVN 由 `svn diff` 给出对 BASE 的差异，Git 由 `git diff HEAD` 给出对 HEAD 的差异，暂存区里的改动也算在内。
- 未纳入版本控制的文件没有差异可算，显示文件内容，按新增对待；二进制与非 UTF-8 文件不给看。
- 未纳入版本控制的目录在 svn 状态里只有一行，页面上展开成里面的文件；`node_modules`、`dist` 这类依赖与产物目录不展开，文件太多时只列前 200 个。Git 的未跟踪文件由 `git status` 逐个列出，同样限制在 200 个以内。

变更页只读；提交、更新这些会改工作副本的操作在「同步」页做。工作副本有改动时页面会自动刷新：服务端每 3 秒查一次状态，变了就通过 SSE 通知页面。写操作结束后，日志与同步信息也会跟着刷新。

## 同步

「同步」页按工作副本的类型给出对应的操作，执行前弹确认，执行中通过 SSE 一行行推送命令输出。操作在服务端后台执行，关掉页面不会中断；重新打开时如果任务还在跑，会接上继续显示输出。执行中也可以点「取消」终止进程。

- Git 切换分支：列出本地分支，以及还没有同名本地分支的远端跟踪分支。选本地分支直接切；选远端分支会建同名本地分支并设好跟踪关系；也可以从当前提交新建分支。工作区有未提交改动、切换会覆盖时就拒绝，原因留在输出里。
- Git 拉取：默认只快进，也可以选合并或变基。当前分支要有远端跟踪分支；没有就提示先在终端里设，页面不替用户设。
- Git 推送：推到当前分支的远端跟踪分支。没有上游时可以勾选「设置上游并推送」，推到 `origin` 或唯一的远端。不提供强制推送。
- Git 提交：勾选要提交的路径并填写提交说明。先暂存选中的路径再提交，未跟踪、删除与重命名一起处理；索引里如果有未选中的暂存改动，会拒绝提交，避免带上别的东西。
- SVN 更新：跑 `svn update`，冲突按 `postpone` 留着，不替用户取舍。
- SVN 提交：勾选要提交的路径并填写提交说明。冲突、未纳入版本控制、本地缺失的路径先挡住，不发给服务器。

同一工作副本同时只跑一个写操作，撞上时提示等前一个跑完。

拉取、推送、更新与提交都可能要认证。服务端不会弹密码或口令提示：Git 走 credential helper 与 ssh-agent，SVN 用已缓存的凭据。没配好时命令直接失败，页面显示原因；先在终端里完成一次登录或把凭据缓存好，再回到页面操作。

## 提交日志

列出工作副本所在路径最近的提交：版本号（Git 上是短 sha）、作者、时间与提交说明。Git 在本地分支当前提交与远端跟踪分支最新提交旁标出分支名，只在远端分支上的提交标为待拉取，页面顶部显示当前分支领先、落后远端各几个提交；SVN 显示工作副本里最高的版本号，服务器上更新的版本标为待更新。选一次提交，能看到这次改动的路径，点路径看这一版对它的差异，也可以看整次提交的差异。

列表只显示提交说明的第一行，选中后在详情里显示完整说明；一页 50 条，可以点「加载更多」继续往前翻。

Git 在打开日志或刷新时先同步一次当前分支的远端分支，别人新推的提交也能列出来；同步只更新仓库里的远端跟踪分支与对象，不动工作区、暂存区，也不合并。连不上远端时照旧列上次同步到的记录，并在页面上说明。SVN 的日志本来就向服务器查，不用额外同步。

## 浏览目录

左侧是一棵懒加载的目录树，展开一层读一层；右侧显示选中文件的内容，带行号，按扩展名做语法高亮。读的是工作副本磁盘上的文件，未提交的改动也能看到。

- 版本库内部目录与依赖、产物目录（`.svn`、`.git`、`node_modules`、`dist`、`build`、`target` 等）不列出来。
- 二进制、非 UTF-8 与超过 512KB 的文件不给看内容，页面上直接说明。
- 只读，不动工作副本。

## 支持范围

判定工作副本、查状态、算差异、读日志、浏览目录与读文件内容都按登记时的类型走 svn 或 git 命令；浏览目录直接读磁盘。查询类命令只读，不改工作区与暂存区；拉取、推送、更新与提交只在「同步」页显式触发，且默认只接受本机请求。页面不提供 revert、reset、强制推送这类难以撤销的操作。

工作副本变化与操作输出通过 SSE 推送。变化提醒靠服务端每 3 秒查一次 `svn status` 或 `git status`，不是文件系统事件，改动到页面刷新之间最多差一个检查周期。SSE 连接只读，写操作仍走单独的接口并受本机限制。启动时 svn 与 git 装了其中一个即可，添加到工作区时再按该目录实际属于哪种版本控制检查对应命令。
