# dvcsx

网页里看 SVN 工作副本或 Git 仓库的未提交变更与提交日志，点文件直接看差异。

## 用法

```
dvcsx                 起网页界面
dvcsx web             同上
dvcsx web --host 127.0.0.1 -p 8771
```

| 选项 | 说明 |
| --- | --- |
| `--host 地址` | 监听地址，默认 `0.0.0.0`；只想本机用就写 `127.0.0.1` |
| `-p, --port 端口` | 监听端口，默认 0 由系统挑一个空闲的 |
| `-o, --open` | 起来后打开默认浏览器 |
| `--json` | 只打一行地址信息，给脚本起服务用 |

页面没有登录，默认绑所有网卡，同一网络里能连上的人都能看到工作副本里的差异。只想本机用就加 `--host 127.0.0.1`。

## 加工作副本

左侧「添加」，选一个有 `.svn` 的目录，或一个 Git 仓库目录。加的时候先跑 `svn info`，不是 SVN 再按 `git rev-parse` 认，两样都不是就拒绝。登记只记目录本身，不动工作副本。

Git 登记的是仓库里的某个目录，可以就是仓库根，也可以是子目录；是子目录时只显示这个目录底下的改动与提交。

已登记的目录可以移出列表，工作副本本身不受影响。

## 变更

列出工作副本里未提交的改动：改动的、新增的、删除的、重命名或替换的、冲突的、未纳入版本控制的。点一行看差异。

- 已纳入版本控制的文件，SVN 由 `svn diff` 给出对 BASE 的差异，Git 由 `git diff HEAD` 给出对 HEAD 的差异，暂存区里的改动也算在内。
- 未纳入版本控制的文件没有差异可算，显示文件内容，按新增对待；二进制与非 UTF-8 文件不给看。
- 未纳入版本控制的目录在 svn 状态里只有一行，页面上展开成里面的文件；`node_modules`、`dist` 这类依赖与产物目录不展开，文件太多时只列前 200 个。Git 的未跟踪文件由 `git status` 逐个列出，同样限制在 200 个以内。

页面不会提交、更新、revert 或执行任何会改工作副本的 svn 与 git 命令。

## 提交日志

列出工作副本所在路径最近的提交：版本号（Git 上是短 sha）、作者、时间与提交说明，并标出每条是本地已有还是还在远端。选一次提交，能看到这次改动的路径，点路径看这一版对它的差异，也可以看整次提交的差异。

Git 每次取日志前先同步一次当前分支的远端分支，别人新推的提交也能列出来；同步只更新仓库里的远端跟踪分支与对象，不动工作区、暂存区，也不合并。连不上远端时照旧列上次同步到的记录，并在页面上说明。SVN 的日志本来就向服务器查，不用额外同步。

## 支持范围

判定工作副本、查状态、算差异、读日志按登记时的类型走 svn 或 git 命令。除了取 Git 日志前的那次远端同步，其余命令只读，不改工作区与暂存区。启动时 svn 与 git 装了其中一个即可，添加到工作区时再按该目录实际属于哪种版本控制检查对应命令。
