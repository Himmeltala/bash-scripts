# killport

输入端口，杀掉占用它的进程。系统级端口默认拒绝，要显式加 `--force` 才肯动。

## 用法

```
killport 8080                   杀掉占用 8080 的进程
killport 8080 8081 8082         一次给多个端口，逐个处理
killport -n 8080                只列出占用进程，不发信号
killport -9 8080                直接 SIGKILL，不等进程收尾
killport -s INT 8080            发指定信号，名字或编号都行
killport -u 5353                连 UDP 端口一起查
killport -t 10 8080             信号发出后等 10 秒，默认 5 秒
killport -y 8080                跳过确认，超时后补发 SIGKILL 也不再追问
killport --force 3306           受保护端口，确要动就显式放行
killport --help                 显示帮助
```

## 默认行为

先发 SIGTERM，让进程自己收尾。等 `--timeout` 秒仍未退出时，再询问要不要补发 SIGKILL；输入 y 就强杀，输入 n 就保持原样，并提示进程仍在运行。

如果 stdin 不是终端（管道、脚本、CI），没有人可以回答，确认一律按否处理，只提示一句。这种场合要一次处理完，就加 `-y`。

`-9` 跳过等待与追问，直接强杀，用于已经确认要杀的场合。数据库、写文件的进程慎用。

## 保护系统级端口

两个来源，规则一样，都必须显式加 `--force` 才放行：

- 端口 `0` 到 `1023`，即内核只允许 root 绑定的特权端口段。
- 脚本顶部 `PROTECTED_PORTS` 名单里的端口：ftp、ssh、telnet、smtp、dns、http、https、nfs、mysql、postgresql、redis、mongo、kafka、elasticsearch 这些常见服务的默认端口。名单是数组，随手可改。

撞上保护端口时退出码 3，并且不会去查占用进程，直接拒绝。

`8080`、`9090` 这类开发常用的端口故意不列进名单，免得挡住自己的 `spring-boot:run`。真占上了，正常杀掉即可。

## 查占用进程

先执行 `ss -H -ltnp`，用 `sport = :<端口>` 作为过滤条件查监听套接字，再从输出里的 `users:(("java",pid=1234,fd=88))` 摘出 pid。如果 `ss` 不在，就退回 `lsof -nP -t -iTCP:<端口> -sTCP:LISTEN`。两个都没有就报错退出。

加 `-u` 时连 UDP 一起查。TCP 与 UDP 各查一遍，pid 合在一起去重。

拿到 pid 后读 `/proc/<pid>/comm` 与 `/proc/<pid>/cmdline`，把进程名、属主、命令行打出来给人看，确认后再动手。

## 几种查不到进程的情形

- 端口没人监听：提示端口无监听，退出码 1。
- 端口有监听但 `ss` 没给出 pid：非 root 时看不到别人进程的详细信息，容器映射的端口也会这样。脚本只报告，不动手，也不做任何猜测。
- pid 是 `1`、本脚本自身、或本脚本的父进程：跳过。脚本可能被子 shell 调起，猜错一次就是杀掉 init 或自己所在的进程组。
- 发送信号失败：多半是进程已经退出或权限不足；脚本逐条报告，不中断后面端口的处理。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部处理成功 |
| 1 | 有端口没处理成：没人监听、拿不到 pid、信号没送到、进程没退出 |
| 2 | 用法错误，与 `mvnx` 一致 |
| 3 | 撞上受保护端口，且没有 `--force` |

多个端口一起给时，只要有一个没处理成，整体就非零。撞保护端口（3）比一般的没杀成（1）更值得调用方看见，两者同时出现时按 3 退出。

## 实现上要注意的坑

- **校验函数不能靠命令替换回传结果。** 命令替换会开子 shell，`usage_error` 里的 `exit` 只退掉子 shell，主流程会带着空端口继续往下跑，表现为报完错又照常去查 0 号端口。校验结果写进全局变量。
- **`ss` 的过滤条件是单个参数。** 端口号必须跟着冒号拼成 `"sport = :8080"` 传进去，拆成两个参数会被当成两段独立条件。
- **端口号按十进制解析。** 用 `$((10#$p))`，否则 `080` 这类前导零会被 bash 当成八进制；位数先卡一道，超长数字交给 `$((10#...))` 会直接报错退出。
- **命令行里可能带换行。** `python3 -c` 这类进程的 `cmdline` 里就会出现换行；如果不压平，输出的表格会被冲散。
- **`ss` 看不到 pid 不等于端口空闲。** 有输出行但摘不到 pid，是「拿不到」而不是「没人占用」，两种情况要分开报。
