# zipx

把 `zip` 与 `unzip` 常用的几种组合收进一个界面：压缩、解压、查看与校验、包内增删。不带参数时打开菜单，先选动作再勾目标；带参数时直接执行，也方便写进脚本。本工具只管 zip 包，不管 tar.gz 与 7z。

## 用法

```
zipx                     打开菜单
zipx pack 目录 文件       打包，默认排除 .git、target、node_modules 等
zipx pack -o 名字.zip 目录
zipx unpack 包.zip        解到当前目录
zipx unpack 包.zip -d 目标目录
zipx extract 包.zip 条目  只提取包内指定条目
zipx list 包.zip          列出包内文件
zipx test 包.zip          校验包的完整性
zipx add 包.zip 文件      追加进已有包，撞上同名条目时按更新处理
zipx rm 包.zip 条目 -y    删包内条目
zipx -n ...               只打印要执行的命令，不落盘
zipx --help               显示帮助
```

界面自绘，用方向键移动，用空格勾选，用回车确认。输入框按回车确认、Ctrl+C 取消，确认框按 y 确认，文本查看按 q 关闭。

非交互环境（管道、脚本、CI）下探不到终端时，自动退回编号输入：菜单列成编号让人选一个，复选让人一次输入多个编号。输入用尽后按取消处理，退出码为 3。

## 缺省与省略

- 不带参数时打开菜单；只给了条目、没给动作时，按 `pack` 处理。第一个参数是 `.zip` 时，脚本会提示「没写动作，按压缩处理；解包用 zipx unpack」，这是最容易搞错的一步。
- 包名默认取当前目录名加 `.zip`，用 `-o` 换。
- 解压目标目录默认当前目录，用 `-d` 换，目录不存在时会新建。
- `pack` 的动作是压缩，不是解压；`unpack` 才是解压。

## 安全约定

以下三件事都要求用户确认后才执行：

- **已有的包不静默覆盖。** `pack` 撞上同名包时直接拒绝，要覆盖必须加 `--overwrite`。包里可能是上一次打包的内容，覆盖后无法恢复。
- **解压默认不覆盖同名文件**（`unzip -n`），要覆盖必须加 `--overwrite`（`unzip -o`）。解压出错最常见的后果是覆盖别人的文件。
- **删除包内条目前先确认。** 交互时弹出一次确认框；非交互环境不给 `--yes` 就直接拒绝，因为 `zip -d` 直接从包里摘掉条目，没有回收站。

解压前先看一遍包内条目名，绝对路径、Windows 盘符、含 `..` 的条目一律拒绝执行。这类包解出来会写到目标目录之外（zip slip）。unzip 6.00 自己会拦一部分，但各版本行为不一致，不指望它。

## 默认排除

`pack` 默认跳过 `.git`、`.svn`、`.idea`、`node_modules`、`target`。这几类要么是版本库元数据，要么是构建产物与依赖，塞进包里只会让包变大。排除规则加在被选中条目那一层之下：选中 `proj` 时，排掉的是 `proj/.git` 与它下面的所有内容。显式选中的条目本身不排除，选 `.git` 就是要它。`--no-exclude` 关闭默认规则；`--exclude 模式` 再追加一条自己的规则，按 zip 的规则匹配归档内路径，可以重复指定。

## 中文文件名

两种情况分开看：

- **用新版 zip 打的包，解压正常。** zip 3.0 编译时带了 `UNICODE_SUPPORT`，locale 为 UTF-8 时自动给非 ASCII 名置 UTF-8 标记（`flag_bits` 为 `0x800`），Windows 解压中文名正常，不需要额外加 `-UN=UTF8`。
- **老工具在 Windows 上打的包会是乱码。** 这类包把 GBK 字节直接写进条目名，并且不置 UTF-8 标记，unzip 会按 cp437 解出 `╛╔░ⁿ╬─╝■` 这样的框线字符。unzip 6.00 **不支持**指定包内编码，加 `-O` 会报用法错，退出码为 10，所以在 unzip 6.00 上没有干净的解法。脚本探测到这种条目名时会提示一句，要正常显示只能改用 7z、bsdtar 这类工具。

探测依据的是字符本身：正常文件名不会成片出现框线与块字符（`U+2500` 到 `U+259F`、`U+25A0` 到 `U+25FF`），用 `grep -P` 查一遍。字节层面验不出来，因为 unzip 已经把名字转成本地编码了。

## 退出码

| 码 | 含义                                                           |
| -- | -------------------------------------------------------------- |
| 0  | 成功                                                           |
| 1  | 操作失败：包读不了、包坏了、zip 没有可打包的东西、找不到条目等 |
| 2  | 用法错误，与 `mvnx`、`killx` 一致                       |
| 3  | 用户取消：菜单里按取消、菜单模式输入用尽、删条目没确认         |

`unzip` 自己的失败码有 9、10、50 这些，脚本统一收成 1，调用方按上表判断即可，不必去查 unzip 的码表。

## 行为细节

- 空目录会存成目录项，解压时也建出来。
- 符号链接默认跟随，存的是链接指向的内容，解出来是一份普通文件副本。要存链接本身得给 zip 加 `-y`，本工具没开放这个开关。
- 坏掉的符号链接：zip 报 `zip warning: name not matched` 并跳过该条目，其余照常打包，退出码不变。
- 条目名与包名带空格都正常，命令打印时按 `%q` 转义，复制粘贴回去能直接跑。
